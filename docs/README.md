# CareerPilot 开源学习营

把一个可运行的 AI 应用，拆成一条可以跟着做、做完能证明、遇到问题能排查的工程实践路线。

这不是“把所有技术文档堆在一起”的目录，而是一个小型开源课程：每一节只解决一个能力问题，每一步都要求留下运行结果、测试结果或设计解释。

## 先看这一页

### 你最终要拿走什么

- 一次可复现的本地运行记录：知道服务、数据库、降级探针分别如何验证。
- 一张真实请求链路图：能从 SSE 入口追到路由、检索、专家、仲裁和上下文组装。
- 一份 RAG 评测结果：使用仓库测评集，能解释 Recall、MRR、章节命中和不可回答通过率。
- 一组工程取舍卡片：能说明为什么使用混合检索、受控图谱扩展、记忆同意和熔断降级。
- 一个可验收的小扩展：新增评测用例、排障卡片或业务能力，并写清验证证据。

### 推荐入口

1. [00｜先跑通项目](learning-path.md#00-先跑通项目)：30 分钟确认环境和最小闭环。
2. [学习专栏目录](learning-path.md)：按顺序完成 8 个主题，每个主题都有产出物和通过条件。
3. [作业与验收](practice.md)：不要只读；选择一个作业，把证据留下来。
4. [固定学习模板](lesson-template.md)：新增文档时沿用同一套结构，避免重新变成散乱说明书。
5. [故障与 Badcase 卡片](badcases.md)：把“跑不起来”和“结果不好”拆成可定位的问题。

### 打卡区：留下你的进度

- [学习打卡模板](progress.md)：每次只记录一个目标、一个动作和一条证据。
- 打卡不是日报；没有可复现证据的内容标记为“待验证”。
- 一个 Badcase 修复、一个评测回归或一个可解释的设计取舍，都可以作为有效打卡。

## 使用规则

每次学习只保留一条证据链：

```text
目标 → 入口代码 → 可执行动作 → 观测结果 → 设计解释 → 下一步作业
```

如果一个结论没有命令、测试、页面结果、日志或代码定位支撑，就把它标为“待验证”，不要把它写成已完成能力。文档中的开发默认值也不等于生产配置，生产边界见[安全与隐私](security-privacy.md)。

## 当前版本

- 路线定位：AI 应用工程化实战，不是 LangChain4j API 速查。
- 适合对象：能阅读 Java/TypeScript，想理解 RAG、Agent 和生产治理如何串成闭环的开发者。
- 维护方式：新增能力先补“目标、代码入口、验收证据和 Badcase”，再进入参考库。
