# 学习打卡模板

## 一次打卡只完成一件事

```text
日期：
专栏编号：00 / 01 / 02 / 03 / 04 / 05 / 06 / 07
今天要证明的结论：
我执行的动作：
证据位置：命令输出、测试名、截图、指标 JSON 或代码路径
我发现的边界：
下一步：
```

## 路线进度

- [ ] 00｜先跑通项目：健康检查、就绪检查、核心页面
- [ ] 01｜追踪一次聊天请求：入口、SSE、上下文、失败收口
- [ ] 02｜拆开混合检索：策略对比、Gold、失败分类
- [ ] 03｜理解多智能体编排：路由、并发、仲裁、预算
- [ ] 04｜记忆、上下文与隐私：准入、召回、撤回、降级
- [ ] 05｜从岗位缺口到成长任务：前置关系、证据、幂等
- [ ] 06｜跑一次真实 RAG 评测：测评集、指标、样本复盘
- [ ] 07｜做一次工程化扩展：代码、测试、文档、回归

## 好打卡和普通打卡的区别

| 普通记录 | 有效打卡 |
| --- | --- |
| “今天看了 RAG” | “对 q017 分别跑 vector_only 和 fused，确认 Gold 节点从 TopK=5 之外进入 TopK=3；证据见结果 JSON。” |
| “Neo4j 挂了” | “`/healthz=200`、`/readyz=503`；聊天走向量降级；没有输出图谱引用；日志 traceId 为……” |
| “优化了准确率” | “同一测评集、同一配置下，multi-hop Hit 从 A 变为 B；失败样本 q003、q019 的根因从 multi_hop_miss 变为……” |

## 每周复盘

完成 2～3 次打卡后，补下面三句话：

1. 本周最重要的一个工程不变量是：______。
2. 本周最值得保留的一个失败样本是：______。
3. 下一周只验证一个假设：______。
