# 作业与验收

## 作业规则

这里的作业不是读后感，而是一个最小可验证任务。每次提交至少包含：

```text
作业编号：
目标：
改动或操作：
证据：命令输出 / 测试名 / 页面截图 / 指标结果
结论：通过、部分通过或阻塞
如果失败：根因假设和下一步动作
```

## 验收评分

| 维度 | 分值 | 通过表现 |
| --- | ---: | --- |
| 能运行 | 20 | 命令可复现，环境和前置条件写清楚 |
| 能解释 | 25 | 能说明入口、数据流、约束和取舍 |
| 有证据 | 25 | 结论能回溯到测试、日志、页面或指标 |
| 看边界 | 20 | 至少验证一个失败、超时、空结果或不可用依赖 |
| 能扩展 | 10 | 提出一个小改动并写清回归方式 |

80 分可进入下一节；低于 80 分先补齐证据，不需要重复抄代码。

## 作业 1：建立最小运行证据

### 任务

启动依赖、后端和前端，记录健康检查与就绪检查。

### 交付

- `/healthz` 和 `/readyz` 的结果。
- 一个核心页面截图。
- 一张依赖表：PostgreSQL、Neo4j、LLM、OSS 分别影响哪些功能。

### 验收

- 进程存活和依赖就绪没有混为一谈。
- 如果某依赖未启动，记录用户能做什么、不能做什么。

## 作业 2：追踪一次聊天请求

### 任务

选择一个“岗位匹配”或“学习规划”问题，从控制器开始，追踪到最终 SSE 事件。

### 交付

- 5～8 个代码入口组成的链路图。
- 每一段的输入和输出。
- 一个单专家超时或引用缺失时的处理说明。

### 验收

- 不使用“框架自动处理”作为解释。
- 能指出用户隔离、事件顺序和引用护栏分别在哪里生效。

## 作业 3：跑一次真实 RAG 评测

### 任务

使用 `evals/rag_testset.json` 跑小样本，再跑完整测评或前端评测页面。

```powershell
node evals/run_eval.mjs --smoke
```

### 交付

- 测评集版本、样本量、Top-K 和阈值。
- Recall@K、MRR@K、证据锚点命中和不可回答通过率。
- 5 条失败用例的根因分类。

### 验收

- 每个指标能回到具体样本。
- 不把“回答写得像”当成检索命中。
- 至少提出一个基于失败分类的下一轮实验。

## 作业 4：验证 Neo4j 降级

### 任务

在本地测试环境让 Neo4j 暂不可用，观察健康检查、聊天请求、日志和最终答案的差异。操作前先确认容器名称，避免误停无关服务。

### 交付

- 依赖正常和 Neo4j 不可用时的两组结果。
- 熔断打开、半开或恢复的观测证据（以实际日志/接口为准）。
- 一句话说明降级后哪些结论不能再声称由图谱证明。

### 验收

- `/readyz` 的严格失败不会被误写成整个应用崩溃。
- 普通回答不会伪造图谱证据。
- Neo4j 恢复后能回到正常路径，或明确记录恢复条件。

## 作业 5：检查记忆准入

### 任务

设计两条应该记住和两条不应该长期记住的信息，结合用户同意、PII 脱敏和外部记忆不可用场景验证。

### 交付

- 4 条样例及准入结论。
- 记忆写入、召回、撤回和删除的边界。
- Mem0 不可用时的用户可见行为。

### 验收

- “有用”不等于“允许持久化”。
- 不能用降级策略绕过用户同意或数据删除。

## 作业 6：提交一个小扩展

### 任务

从学习路径 07 的题目中选择一个，完成最小改动。

### 交付

代码或评测数据、自动化测试、文档、回归结果和回滚说明。

### 验收

改动同时具备“行为、证据、边界、文档”四件套；只提交截图或只提交代码都不算完成。
