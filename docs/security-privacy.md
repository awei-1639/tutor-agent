# 安全与隐私边界

## 1. 发布前原则

开源仓库只包含代码、脱敏样例和可再生成的评测资料，不包含真实 API Key、JWT 密钥、数据库密码、用户简历、对话、个人画像、未获授权的全文资料和生产 OSS 配置。

## 2. 认证与会话

当前认证使用 Cookie 携带会话信息，核心防护包括：

- HttpOnly Cookie，降低脚本读取 Token 的风险；
- 生产环境 Secure Cookie；
- Refresh Token 轮换，刷新后旧 Token 失效；
- 服务端重新查询用户状态和角色，不信任前端菜单或旧 JWT；
- 已认证写请求要求 CSRF 双提交 Cookie 和 `X-CSRF-Token` 请求头。

认证入口和内部评测入口有特殊豁免，但生产 profile 会关闭开发登录和内部端点。

内部评测端点在开发环境中也默认只接受本机回环请求；运行指标端点不再匿名访问，监控系统应使用受保护的访问路径。

## 3. 用户数据隔离

会话、画像、简历、学习计划、记忆和通知都必须以当前用户身份查询。后台管理端额外要求数据库中的 `role = ADMIN`，并检查账号没有被禁用或软删除。

开发时新增接口必须回答：

1. 用户 ID 从哪里获得？
2. SQL 是否带用户条件？
3. 管理员是否需要单独权限？
4. 日志中是否会泄露个人内容？

## 4. 简历与 PII

简历原文和 PII 映射使用服务端配置的加密密钥处理。`RESUME_ENC_KEY` 缺失时不应接受需要保护的简历上传。

日志和评测数据不得记录完整手机号、邮箱、身份证号、地址或原始简历。对外部记忆服务写入前必须进行脱敏。

## 5. Mem0 数据边界

Mem0 默认关闭。启用时必须由用户开启外部记忆授权，只写入经过筛选和脱敏的长期信息，按用户 ID 隔离，并支持按用户清理。超时、失败和熔断时回退本地 Episode 记忆；远程删除失败必须明确提示用户。

## 6. OSS 文档边界

知识库原文件应放在私有 Bucket。AccessKey 只由后端读取，前端不应获得永久访问凭证。

上传流程当前支持 PDF、DOCX、TXT 和 Markdown；文档处理采用异步状态：`uploaded`、`processing`、`indexed`、`failed`、`deleted`。

正式部署前还应在网关层补充 HTTPS、请求体大小限制、上传频率限制、恶意文件扫描、OSS 生命周期和审计。

## 7. LLM 安全边界

外部模型输入遵循最小必要原则。不要把完整数据库记录、全部会话历史或未脱敏简历直接拼入 Prompt。

LLM 返回的路由、工具参数和多跳决策必须经过服务端枚举、字段、类型和范围校验。模型不能直接执行任意 SQL、Cypher 或文件操作。

项目还提供单轮和每日 Token 预算、实例级并发闸门、超时和调用失败回退。

## 8. 当前已知限制

- 单实例内存限流不等于多实例全局限流；生产多实例应使用 Redis 等共享方案；
- 开发 Docker Compose 使用默认密码时只能用于本地；
- 安全日志、告警和密钥轮换需要由部署环境补齐；
- 文档上传仍应在正式部署前补充恶意文件扫描；
- RAG 引用评测仍需更多人工校准。
