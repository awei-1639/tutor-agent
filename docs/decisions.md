# 关键设计决策

本文档记录当前实现背后的工程取舍。它不是“所有方案都正确”，而是说明为什么在当前项目规模和学习目标下选择了这些方案。

## ADR-001：按 Query 类型选择检索链路

**背景**：向量、关键词、图扩展和 Rerank 的收益与成本并不相同。

**决策**：先路由 Query，再选择检索组合。资源推荐可以启用 Rerank；学习路径启用受控多跳；越界请求跳过检索。

**收益**：降低无效调用，保留不同场景的质量目标。

**代价**：需要维护 Query 分类规则和切片评测，不能只用一个总体平均数判断效果。

## ADR-002：使用 RRF 融合不同检索通道

**背景**：向量相似度、pg_trgm 分数和图路径分数没有天然可比性。

**决策**：先得到各通道排名，再用 RRF 融合；图扩展和稀疏通道分别设置衰减，并限制候选配额。

**收益**：避免直接相加异构分数，且便于通过排名和切片结果调参。

**代价**：RRF 只利用排名，不直接利用原始相似度；参数仍需在真实数据集上校准。

## ADR-003：多跳检索由服务端设上限

**背景**：让 LLM 自由决定跳数容易造成循环、图爆炸和成本失控。

**决策**：最多 3 Hop，关系白名单、单源配额、总量上限和分数衰减全部由服务端控制；LLM 只能输出结构化的结束/改写决策。

**收益**：保留 Agentic 检索的灵活性，同时保证可预测的资源上限。

**代价**：复杂知识路径可能被截断，需要通过多跳覆盖率识别这类 Badcase。

## ADR-004：Mem0 作为增强项而不是主链路依赖

**背景**：远程记忆服务存在网络延迟、服务不可用和隐私边界问题。

**决策**：本地 Episode 记忆始终作为兜底；Mem0 只有在启用且用户同意时才读写，调用失败通过超时和熔断回退。

**收益**：主聊天链路不受远端服务影响，用户能够控制外部记忆。

**代价**：本地和远端记忆需要去重、删除和一致性处理。

## ADR-005：Rerank 只用于资源推荐

**背景**：Rerank 有额外模型调用成本；图谱关系问题不一定适合按文本相似度排序。

**决策**：资源推荐进入固定大小的候选池后再 Rerank，其他 Query 保留融合排序或图结构排序。

**收益**：把额外成本投向排序收益更明确的场景，避免重排破坏前置关系和岗位技能覆盖。

**代价**：需要维护 Query 识别逻辑，资源识别错误会影响链路选择。

## ADR-006：Neo4j 故障时安全回退 PostgreSQL

**背景**：图谱对学习路径有帮助，但不应成为普通聊天的单点故障。

**决策**：查询级超时 + 进程内熔断。熔断期间图扩展返回空结果，向量/关键词检索继续工作；`/readyz` 仍然如实报告 Neo4j 未就绪。

**收益**：区分“实例是否具备完整依赖”和“单个请求是否可以降级服务”。

**代价**：降级状态下学习路径质量可能下降，需要在日志、trace 和前端状态中标记。

## ADR-007：文档原文件放 OSS，检索数据放 PostgreSQL

**背景**：原文件体积较大，且需要和向量分块分离管理。

**决策**：OSS 使用私有 Bucket 保存原文件；PostgreSQL 保存元数据、状态、分块和 embedding；文档处理异步完成后才进入检索。

**收益**：文件和检索数据职责清晰，支持失败重试和软删除。

**代价**：上传、解析、向量化存在短暂异步状态，需要后台查询状态和重试入口。
